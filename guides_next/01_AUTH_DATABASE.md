# Участник 1 — авторизация и SQLite

Файлы: app.py, database.py, schema.sql, security.py, auth.py, templates/login.html, templates/register.html, .gitignore.
Общая точка подключения модулей — app.py. Согласуйте её изменения с остальными.

Разобраться и проверить:
- create_app создаёт Flask и подключает модули; app = create_app() сохраняет обычный запуск python app.py.
- SQLite хранит пользователей, заказы, позиции, события статусов и временные ограничения входа.
- БД создаётся без ручных SQL-команд в instance/pizza.sqlite3. Схема использует CREATE TABLE IF NOT EXISTS: перезапуск не стирает записи.
- Пароли сохраняются через generate_password_hash (scrypt), проверяются check_password_hash.
- Сессия хранит ID пользователя; роль каждый раз читается из БД. Поле is_admin нельзя назначить регистрацией.
- Все формы POST имеют csrf_token; logout тоже POST.
- Почта: латиница, максимум 254 символа, до 64 перед @, домен с точкой, без пробелов внутри и двойных точек в локальной части. Краевые пробелы убираются, регистр нормализуется. Не все возможные RFC-адреса принимаются: это документированная учебная политика.
- Проверка почты — формат и уникальность, не подтверждение владения ящиком. Письма не отправляются.
- Пользовательский пароль 8–128 символов. admin/admin — отдельное требование учебного задания.
- После 5 неверных попыток для сочетания IP и логина вход временно ограничен на 60 секунд.
